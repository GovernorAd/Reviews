# Reviews

Сайт отзывов об автомобилях с регистрацией и авторизацией: **React 19 + TypeScript + Vite** на клиенте и **Express 5 + Zod** на сервере. Клиент построен по **Feature-Sliced Design**, UI — **Ant Design** и **styled-components**.

Пользователи могут зарегистрироваться, войти в аккаунт, оставлять отзывы об автомобилях и комментарии. Гостям доступен только просмотр — создавать отзывы и комментарии могут только авторизованные пользователи.

Новые отзывы проходят модерацию. Автор после отправки видит статус «На модерации», а в общий список попадают только одобренные отзывы. Администратор управляет очередью на `/admin/reviews`: фильтрует по статусу, одобряет, отклоняет с указанием причины и редактирует содержимое. При отклонении автор получает уведомление с причиной.

На главной странице выводятся по **10 отзывов** с пагинацией. В карточке отзыва есть марка автомобиля, версия, фотография, автор, первые 50 слов текста, дата публикации и ссылка на страницу полного отзыва. Комментарии и удаление собственного отзыва доступны на странице `/reviews/:id`.

В шапке сайта есть меню марок: рядом с каждой маркой показано количество отзывов, а в выпадающем списке — версии этой марки с их счётчиками. Выбор марки открывает `/?brand=...`, выбор версии — `/?brand=...&version=...`. Фильтр можно сбросить на странице списка.

## Быстрый старт

```bash
npm install
npm run dev
```

- Клиент: http://localhost:5173
- API: http://localhost:4000/api
- Health-check: http://localhost:4000/api/health

`npm run dev` запускает сервер и клиент параллельно. Vite проксирует `/api` на порт `4000`.

Создайте аккаунт на `/register` или войдите на `/login` — после этого станут доступны формы отзыва и комментария.

Администратор создаётся при старте сервера. Учётные данные по умолчанию: логин `admin`, пароль `admin12345`. Их можно изменить переменными `ADMIN_USERNAME`, `ADMIN_EMAIL` и `ADMIN_PASSWORD`.

## Аутентификация

- **Регистрация** (`/register`): логин, email, пароль (от 8 символов).
- **Вход** (`/login`): логин и пароль.
- Пароли хранятся как scrypt-хэш с уникальной солью, в API никогда не возвращаются.
- Сессия — JWT (HS256, 7 дней) в **httpOnly cookie** `reviews_session` с `SameSite=Lax`.
- Клиент при старте восстанавливает сессию через `GET /api/auth/me`.
- Создание отзыва и комментария защищено middleware `requireAuth`. Автор берётся из сессии, а не из тела запроса.
- Администратор имеет роль `admin`; админ-маршруты защищены `requireAuth` и `requireAdmin`.
- Удалять отзыв может только его автор (проверка на сервере, кнопка показывается только владельцу).
- Демонстрационные отзывы из сидов нельзя удалить — у них нет владельца.

## Модерация и уведомления

- Новый отзыв создаётся со статусом `pending` и не попадает в публичный список, каталог и меню марок.
- Публично доступны только отзывы со статусом `approved`. Автор и администратор могут открыть отзыв в любом статусе по прямой ссылке.
- Комментарии разрешены только к одобренным отзывам.
- Админ-панель `/admin/reviews` показывает все отзывы. Фильтры: `all`, `pending`, `approved`, `rejected`; в таблице есть марка, автор, статус, дата и действия.
- Администратор может одобрить отзыв, отклонить его с обязательной причиной или отредактировать марку, версию, фото, оценку и текст. Редактирование не меняет статус модерации.
- Одобрение и отклонение создают уведомление автора. Уведомление об отклонении содержит причину. Колокольчик в шапке показывает непрочитанные уведомления и ведёт к отзыву.
- Демонстрационные отзывы из сидов уже одобрены. Уведомления и данные модерации хранятся в памяти и сбрасываются при перезапуске сервера.

### Правила FSD в проекте

- Каждый слайс предоставляет публичный API через `index.ts`, импорты снаружи идут только через него.
- Слой может импортировать только слои **ниже** себя: `app → pages → widgets → features → entities → shared`.
- Внутри слайса — сегменты `ui`, `model`, `api`, `lib`.
- Алиас `@/*` указывает на `client/src/*`.

Новый слайс создаётся как папка с сегментами и `index.ts`. Например, `features/share-review/ui/ShareReviewButton.tsx`.

## API

| Метод    | Путь                             | Доступ        | Описание                          |
| -------- | -------------------------------- | ------------- | --------------------------------- |
| `GET`    | `/api/health`                    | публичный     | Проверка доступности              |
| `POST`   | `/api/auth/register`             | публичный     | Регистрация + сессия              |
| `POST`   | `/api/auth/login`                | публичный     | Вход + сессия                     |
| `POST`   | `/api/auth/logout`               | публичный     | Очистка cookie сессии             |
| `GET`    | `/api/auth/me`                   | авторизованный | Текущий пользователь             |
| `GET`    | `/api/reviews`                   | публичный     | Страница одобренных отзывов       |
| `GET`    | `/api/reviews/catalog`           | публичный     | Марки и версии со счётчиками      |
| `GET`    | `/api/reviews/:id`               | публичный / владелец / админ | Полный текст отзыва |
| `POST`   | `/api/reviews`                   | авторизованный | Создать отзыв на модерацию       |
| `DELETE` | `/api/reviews/:id`               | автор отзыва  | Удалить свой отзыв                |
| `POST`   | `/api/reviews/:reviewId/comments`| авторизованный | Добавить комментарий к одобренному отзыву |
| `GET`    | `/api/admin/reviews`             | админ         | Все отзывы с фильтром по статусу  |
| `PATCH`  | `/api/admin/reviews/:id`         | админ         | Редактировать содержимое отзыва   |
| `PATCH`  | `/api/admin/reviews/:id/status`  | админ         | Одобрить или отклонить отзыв      |
| `GET`    | `/api/notifications`             | авторизованный | Уведомления текущего пользователя |
| `POST`   | `/api/notifications/:id/read`    | авторизованный | Отметить уведомление прочитанным  |
| `POST`   | `/api/notifications/read-all`    | авторизованный | Прочитать все уведомления         |

Query-параметры списка:

- `page` — номер страницы (по умолчанию `1`);
- `limit` — размер страницы (по умолчанию `10`, максимум `50`);
- `brand` — точное название марки, например `BMW`;
- `version` — точное название версии, например `M3`;
- `search` — поиск по марке, версии, автору и тексту;
- `minRating` — минимальная оценка (1–5);
- `sort` — `newest` (по умолчанию), `oldest`, `rating`.

Для `GET /api/admin/reviews` доступен параметр `status`: `all` (по умолчанию), `pending`, `approved` или `rejected`. Ответ дополнительно содержит счётчики:

```json
{
  "data": {
    "items": [],
    "pagination": { "page": 1, "limit": 10, "total": 22, "totalPages": 3 },
    "counts": { "pending": 0, "approved": 22, "rejected": 0 }
  }
}
```

`PATCH /api/admin/reviews/:id/status` принимает `{ "status": "approved" }` или `{ "status": "rejected", "reason": "..." }`. Причина обязательна и должна содержать минимум 5 символов.

Список возвращает `items` и объект `pagination`:

```json
{
  "data": {
    "items": [],
    "pagination": { "page": 1, "limit": 10, "total": 22, "totalPages": 3 }
  }
}
```

Каталог марок возвращает массив с количеством отзывов на марку и на каждую версию:

```json
{
  "data": [
    {
      "brand": "BMW",
      "total": 3,
      "versions": [
        { "version": "M3", "total": 2 },
        { "version": "320i xDrive", "total": 1 }
      ]
    }
  ]
}
```

Формат остальных ответов: `{ "data": ... }`, ошибки: `{ "error": { "message": "...", "details"?: [...] } }`.

Отзывы приходят вместе с массивом `comments`. Комментарий содержит `id`, `reviewId`, `author`, `text`, `createdAt` и `userId` (кроме демонстрационных).

Пример регистрации:

```bash
curl -i -X POST http://localhost:4000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"ivan_petrov","email":"ivan@example.com","password":"password123"}'
```

Сервер вернёт пользователя и `Set-Cookie` с сессией. Создание отзыва:

```bash
curl -X POST http://localhost:4000/api/reviews \
  -H "Content-Type: application/json" \
  --cookie "reviews_session=<token>" \
  -d '{"carBrand":"Toyota","carVersion":"Camry 3.5","rating":5,"text":"Надёжный автомобиль для ежедневных поездок."}'
```

Поле `imageUrl` необязательно: можно передать абсолютный URL фотографии. Если изображение не указано или не загрузилось, клиент показывает локальную заглушку `client/public/cars/placeholder.svg`.

Новый отзыв возвращается со статусом `pending`: он виден автору и администратору, но не попадает в публичный список до одобрения.

Фотографии демонстрационных отзывов лежат в `client/public/cars/`, источники перечислены в `client/public/cars/CREDITS.md`.

## Хранение данных и безопасность

Данные хранятся в памяти и сбрасываются при перезапуске сервера:

- пользователи — `server/src/modules/auth/auth.repository.ts`;
- отзывы и комментарии — `server/src/modules/reviews/review.repository.ts`;
- уведомления — `server/src/modules/notifications/notification.repository.ts`.

Для замены на БД достаточно реализовать те же методы репозиториев.

Что уже сделано:

- пароли хэшируются scrypt с солью и сравниваются через `timingSafeEqual`;
- JWT подписывается секретом из env и проверяется с ограничением алгоритма;
- cookie `httpOnly` + `SameSite=Lax`, флаг `Secure` настраивается через env;
- все входные данные валидируются Zod, лимит размера JSON — 100 КБ;
- автор отзыва и комментария определяется на сервере, подменить его из тела запроса нельзя;
- удаление отзыва проверяет владельца; чужие и демонстрационные отзывы вернут `403`;
- админ-маршруты и редактирование проверяют роль `admin`, отклонение требует причину;
- неопубликованный отзыв виден только автору и администратору, комментарии к нему запрещены.

Logout очищает cookie; сам JWT остаётся валидным до истечения срока (7 дней), так как сессии stateless. Для мгновенного отзыва токенов в production добавьте серверный blacklist или хранилище сессий.

Для production дополнительно стоит включить HTTPS (`COOKIE_SECURE=true`), заменить in-memory хранилище на БД, добавить rate limiting на `/auth/*` и CSRF-защиту при необходимости.
